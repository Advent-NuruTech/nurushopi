# NuruShop brand and storefront system

This document is the persistent visual and implementation reference for NuruShop. New storefront work should extend this system rather than introduce a parallel palette or layout language.

## Color palette

| Role                 | Value     | Usage                                                   |
| -------------------- | --------- | ------------------------------------------------------- |
| Brand primary        | `#009933` | Primary buttons, active controls, prominent badges      |
| Brand strong         | `#006B2C` | Hover states, links, headings, high-contrast green text |
| Brand bright         | `#00C83A` | Accent on dark surfaces and dark-mode green text        |
| Brand ink            | `#004D20` | Deep gradient endpoint and strongest green emphasis     |
| Brand surface        | `#EFFCF3` | Subtle green backgrounds                                |
| Brand surface strong | `#DDFBE5` | Selected/supporting backgrounds                         |
| Brand border         | `#B8F5C8` | Green-tinted borders and separators                     |

Slate remains the neutral family for page backgrounds, borders, body text, and dark mode. Rose/red is reserved for discounts, errors, and unavailable states. Amber is reserved for ratings, warnings, and low stock. Those semantic colors are not competing brand colors.

The shared tokens are declared in `apps/web/app/globals.css` and should be preferred in new components.

## Homepage behavior

The homepage product area is one continuous responsive grid. Category order can influence product ordering, but a category must not create its own grid or reserve a partially empty row. Products from the next category flow into the next available cell.

Category navigation appears as discovery modules inside the product feed at measured intervals. This keeps category navigation useful during scrolling without presenting a large category directory only once or interrupting every category with a full-width header.

Promotional banners, wholesale picks, and admin-configured merchandising collections use the same insertion system. Available module types alternate automatically after a measured number of products. Removing or adding a data source must rebalance the insertions without changing the relative order of products. These modules use ordinary grid cells rather than separate horizontal rails, which keeps the page continuous and eliminates empty rows.

The unfiltered `/shop` route reuses this blended feed while preserving the newest-first catalog order returned by the data layer. When a category or search filter is active, unrelated promotions and wholesale items are suppressed so the result set remains clear and trustworthy.

## Product detail hierarchy

The expected purchase flow is:

1. Product image and thumbnails.
2. Category context and product title.
3. Rating and verified-review count.
4. Current price, original price, and savings.
5. Stock availability.
6. Quantity and primary purchase actions.
7. Delivery, support, and tracking reassurance.
8. Full product details.
9. Verified reviews.
10. Related products.

Primary purchase actions use brand green. Discount color must not be reused for ordinary navigation or branding.

## Rendering reliability

All text that appears in server-rendered Client Components must have identical output in Node and the browser. Price output is always generated by `apps/web/lib/formatPrice.ts`, which intentionally uses deterministic string formatting instead of runtime-specific currency localization.

Time-dependent values such as “New” are calculated in the server view-model layer and passed to client components. Locale-specific dates should either receive an explicit, stable format or render only after client mount when personalization is required.

Storefront code must also support mobile browsers and embedded WebViews that lack newer Web APIs. Feature-detect capabilities such as `crypto.randomUUID` and retain a non-security fallback for anonymous analytics identifiers. Test the fallback itself rather than relying only on desktop support.
